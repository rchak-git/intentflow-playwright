STRICT FRAMEWORK CONSTRAINTS & SCHEMAS
--------------------------------------------------------------------------------

1. UI MAP SCHEMA (TypeScript):
   - Every entry in `UiMap` is a record mapping a `fieldKey` string to a `UiMapEntry`.
   - `UiMapEntry` requires:
     * `widgetType`: 'TEXTBOX' | 'BUTTON' | 'GENERIC' | 'DROPDOWN' | 'REGION' | 'LINK'
     * `strategy`: 'role' | 'text' | 'label' | 'placeholder' | 'css'
   - Allowed optional properties per strategy:
     * 'role': `role` (e.g., 'button', 'link', 'textbox', 'region', 'alert'), `name` (string or RegExp), `exact` (boolean)
     * 'text': `text` (string or RegExp), `exact` (boolean)
     * 'placeholder': `text` (string)
     * 'label': `text` (string)
     * 'css': `selector` (string)
     * General optional: `timeout` (number in ms)

   DO NOT re-declare 'UiMapEntry' or 'UiMap' types in the output file. 
   ALWAYS import them from the framework types path:
   import type { UiMap, UiMapEntry } from '../../framework/types/uiMap.types';

2. YAML TEST SUITE SCHEMA (YAML):
   - Root keys:
     * `page`: Page object class name (string)
     * `description`: Overview (string)
     * `uiMap`: Path to registry file (string)
     * `sharedScenarios`: Record of reusable scenario flows
     * `profiles`: Record of data profiles
   - Scenario Object:
     * `description`: string (optional)
     * `refScenario`: string referencing another sharedScenario (optional)
     * `steps`: List of `StepIntent` objects (used for base scenarios)
     * `additionalSteps`: List of `StepIntent` objects (used when `refScenario` is present)
   - StepIntent Object:
     * `step`: Step narrative (string)
     * `fieldKey`: Must match a key defined in the UI Map (string)
     * `intent`: 'populate' | 'click' | 'verify'
     * `assertion` (required if intent === 'verify'): 'VISIBLE' | 'NOT_VISIBLE' | 'HIDDEN' | 'DISABLED' | 'ENABLED' | 'CONTAIN_TEXT' | 'HAS_TEXT'
     * `value` (optional for populate/verify): Hardcoded string OR dynamic reference `${data:fieldName}`
   - Profile Object:
     * `usesScenario`: Name of the target sharedScenario (string)
     * `data`: Key-value map of variable names matching `${data:fieldName}` in scenarios
     * `verifications`: List of inline `StepIntent` objects for profile-specific teardown/checks (optional)

3. PLAYWRIGHT SPEC RULES (TypeScript):
   - All generated test methods MUST be placed inside a single `test.describe` block named after the page module.
   - Imports required:
     * `test` from '@playwright/test'
     * `CommandDispatcher` from engine path
     * `loadSuiteYaml` from utils path
     * `getBaseUrl` from envResolver path (`../../framework/utils/envResolver`)
   - Suite loading (`loadSuiteYaml`) MUST occur strictly within a `test.beforeAll` hook.
   - Dynamic environment navigation (`await page.goto(getBaseUrl())`) MUST occur strictly within a `test.beforeEach` hook. Never hardcode static URLs inside `page.goto()`.

   Example Test Method Spec File:
   import { test } from '@playwright/test';
   import { CommandDispatcher } from '../../src/engine/commandDispatcher';
   import { loadSuiteYaml } from '../../src/engine/yamlLoader';
   import { getBaseUrl } from '../../src/utils/envResolver';

   test.describe('McGraw Hill Student Authentication', () => {
     let suite: any;

     test.beforeAll(() => {
       suite = loadSuiteYaml('tests/suites/mheLoginSuite.yaml');
     });

     test.beforeEach(async ({ page }) => {
       await page.goto(getBaseUrl());
     });

     test('TC_LOGIN_001: Verify Valid Student Credentials Submit Successfully', async ({ page }) => {
       const dispatcher = await CommandDispatcher.fromSuite(suite);
       await dispatcher.executeProfile(page, 'validStudentLoginProfile', suite);
     });
   });
