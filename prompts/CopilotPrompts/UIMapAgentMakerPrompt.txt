### Step 2: Create the Portable Agent Files
Create the following files in the repository:

1. **`AGENTS.md`** (at the repository root) — The single source of truth for the UI Map Builder agent. Bake in ALL of these exact rules and workflows:

   - **Dynamic Schema Reading & Strict Type Compliance (Zero Type Drift):**
     - Always read `src/types/uiMapTypes.ts`, `src/types/intentSchema.ts`, and `src/registries/UiMapIndex.ts` directly from the workspace before generating or modifying any UI Map.
     - **Strict Enum Compliance:** Strictly adhere to the exact union string literal values defined in `src/types/uiMapTypes.ts` for `WidgetType` and `LocatorStrategy`. Do not invent unmapped types or guess casing.
     - Generate declarative TypeScript dictionary objects (`Record<string, UiMapEntry>`) ONLY — never generate classes, `(page) => ...` functions, async methods, or Page Object Models.
     - Never output empty strings for optional properties (e.g., never output `text: ''`).

   - **File Naming, Placement & Registry Synchronization (`UiMapIndex.ts`):**
     - Place UI Map files under `src/registries/<AUT_Directory>/<camelCasePageName>.map.ts` (preserving exact directory casing, e.g., `src/registries/Moodle/`, `src/registries/Mhe/`, `src/registries/Angular/`, `src/registries/React/`).
     - Export `export const <PascalCasePageName>UiMap: Record<string, UiMapEntry> = { ... }` with keys named `<pagePrefix>_<elementDescription><WidgetType>` (e.g., `moodle_participants_searchInput` or `mhe_login_submitButton`).
     - **Key Collision Prevention:** Ensure key names include a distinct page/component qualifier to prevent key collisions when spread into consolidated domain maps (e.g., `MOODLE_UI_MAP`).
     - **Mandatory Registry Sync:** Inspect `src/registries/UiMapIndex.ts`. If `<PascalCasePageName>UiMap` is not yet registered, update `src/registries/UiMapIndex.ts` to:
       1. Import `{ <PascalCasePageName>UiMap } from './<AUT_Directory>/<camelCasePageName>.map'`.
       2. Spread `...<PascalCasePageName>UiMap` into the corresponding consolidated domain map (e.g., `MOODLE_UI_MAP`, `MHE_UI_MAP`).
       3. Register BOTH `<PascalCasePageName>UiMap` and `<camelCasePageName>UiMap: <PascalCasePageName>UiMap as Record<string, UiMapEntry>` in `UI_MAP_REGISTRY`.

   - **Reaching Authenticated / Deep Target Pages:**
     - *Auto-Discovery First:* Search `tests/suites/**/*.yaml` for an existing profile or `refProfile` that navigates to the target page (matching by page name, URL, or domain keywords) so the tester does not have to supply a test path manually.
     - *Session Capture:* Run `npx tsx src/cli/reachPage.ts --suite <discovered-yaml> --profile <discovered-profile>` to reach the target state, save `playwright/.auth/state.json`, and print `TARGET_URL=...`, then inspect the live page via Playwright MCP (`browser_navigate` -> `browser_snapshot`).
     - *Auth State Fallback:* If `playwright/.auth/state.json` is missing, expired, or redirects to an SSO login block, pause execution and prompt the user to perform an interactive login session or supply a valid session state before proceeding.
     - *Fallback:* If no matching suite exists, check `.env` for base URL/credentials (never hardcode secrets) and navigate interactively via Playwright MCP, or ask the user if MFA/manual steps are required.

   - **Main Flow (MF-1) — Scenario-Scoped Extraction:**
     - Parse the provided User Story / manual test cases (Gherkin or plain steps) to extract ONLY the actionable UI controls exercised by the tests—never capture ambient noise (column sorting links, static page counters, decorative headers) unless explicitly requested.
     - Infer `widgetType` and required `subSelectors` / `columns` from the test actions and assertions.

   - **Alternate Flow 1 (AF-1) — Non-Destructive Delta Updates:**
     - When updating an existing `.map.ts` file, **NEVER** rename, delete, or modify existing keys, strategies, selectors, `columns`, or existing `subSelectors` unless explicitly instructed to fix a broken locator.
     - Deduplicate first: if an existing key already targets the requested DOM element, reuse and report it.
     - Append only new delta keys (or newly required `subSelectors` / `columns` on an existing composite entry) and conclude with a diff summary: **Reused Keys**, **Added Delta Keys**, and **0 Existing Keys Modified**.

   - **Alternate Flow 2 (AF-2) — Interactive State-Dependent Elements:**
     - For modals, tabs, drawers, or portaled dropdowns (`[role="listbox"]`, `[role="dialog"]`, `.cdk-overlay-container`), trigger the UI state via Playwright MCP (`browser_click`, `browser_type`), capture a fresh `browser_snapshot`, and map the revealed controls.

   - **Alternate Flow 3 (AF-3) — Exploratory Scaffolding:**
     - If no test cases are provided, scan `<main>` (excluding global header/footer boilerplate) and annotate inferred `widgetType` entries with `// TODO: verify widgetType`.

   - **Locator Strategy & `getByRole` Strict-Mode Rules:**
     - **Upgrade from Legacy Static Prompt:** Because the agent inspects the live accessibility tree via Playwright MCP `browser_snapshot`, `strategy: 'role'` (`role` + `text`) IS allowed and preferred **when and only when** the `(role, name)` pair is strictly unique on the page.
     - **Strict-Mode Guard:** If duplicate `(role, name)` matches exist on the page, forbid bare `strategy: 'role'` (to prevent Playwright strict-mode failures) and use `strategy: 'label'`, scoped `css` (`:has()`), or relative `xpath` anchored to a unique parent landmark/heading.
     - **Reject Dynamic Framework IDs:** Never use auto-generated IDs or hashes (`#mat-select-45`, `_R_...`, `_ngcontent-*`, dynamic `css-*` hashes, random UUIDs).
     - **Iframe Resolution (`frameSelector`):** Whenever a control or composite container sits inside an `<iframe>`, include `frameSelector: 'iframe[...]'` directly on the `UiMapEntry`.

   - **Widget-Specific Structural Contracts:**
     - **`RADIO_GROUP`:** Anchor to shared `name`, `<mat-radio-group>`, or `[role="radiogroup"]`; include `subSelectors: { option: 'mat-radio-button, .MuiRadio-root, [role="radio"]', label: '.mdc-label, label' }` (avoid bare `input[type="radio"]` for custom UI libraries).
     - **`CUSTOM_SELECT` & `SEARCH`:** Prefer `strategy: 'label'` or scoped `css` (`:has()`). Define `subSelectors` (`overlayPanel` for body-portaled overlays like `.cdk-overlay-container` or `[role="listbox"]`, `option` / `optionItem`, and `clearBtn` where applicable).
     - **`CARD` & `CONTAINER`:** Top-level `selector` MUST be a generic, un-parameterized container selector matching all instances (never hardcode `${anchorText}` or item text in the top-level `selector`); put relative child selectors inside `subSelectors`.
     - **`WEB_TABLE`:** Use `widgetType: 'WEB_TABLE'` (never `'TABLE'`) with `selector` (table/grid root without text filters), `rowSelector` (e.g., `'div[role="row"], tbody tr'`), and 1-based `columns: { <colName>: { index: 1, controlType: 'LINK' | 'BUTTON' | 'SELECT' | 'TEXT', subSelector: '...' } }`. Map floating row action menus separately as `widgetType: 'MENU'`.

   - **Exception Guardrails & Deterministic Verification:**
     - Never hallucinate locators for missing or ambiguous elements; emit a clear warning in the final output instead.
     - Always run `npx tsc --noEmit` after creating or updating any `.map.ts` file or `UiMapIndex.ts` and resolve all TypeScript errors before finishing.
